# Claude Code setup

This project is developed with AI assistance under a **spec-driven** workflow. This document records
what configuration exists, and proposes (but defers) specialized review agents.

## What exists today

- **`CLAUDE.md`** (repo root) — concise project rules loaded into every Claude Code session: the
  spec-driven flow, module boundaries, Domain import bans, key commands, and the "no commit/push
  without asking" rule. This matches the maintainer's global convention that project-specific rules
  live in the repo's `CLAUDE.md`.
- **`.claude/commands/opsx/` and `.claude/skills/openspec-*`** — generated by `openspec init --tools
  claude`. These are the OpenSpec slash-commands/skills (new/continue/apply/archive/validate…). They
  are OpenSpec's, not hand-authored, and should be updated via `openspec update`, not edited by hand.

The SignalFlow reference repository has **no** `.claude/`, `CLAUDE.md`, or agent configuration — so we
are not copying any agent scaffolding from it. We add only what earns its place.

## Proposed review agents — **deferred** (do not create yet)

Claude Code supports project subagents as Markdown files under `.claude/agents/` (front-matter:
`name`, `description`, `tools`, optional `model`; body = the agent's system prompt). They **review
and recommend**; they must not edit the same areas simultaneously or invent contradictory
architectures.

**Decision: defer creating these until there is Swift code to review** (target: during Phase 1
implementation, once `Sources/` exists). Creating empty or speculative agent files now would be
ornamental. When we do add them, keep the set minimal and non-overlapping:

| Agent | Reviews | Introduce when |
| --- | --- | --- |
| `architecture-reviewer` | dependency direction, forbidden imports, module boundaries, composition root, `Sendable`/actor isolation, correct `@MainActor` use, accidental FFmpeg/AVFoundation/SwiftUI dependency in Domain | first `Sources/` targets land (Phase 1) |
| `audio-analysis-reviewer` | units; linear vs log scales; dBFS/RMS/LUFS/true-peak correctness; FFT windows/overlap; time vs frequency resolution; tolerances; normalization; confidence levels; evidence vs inference separation | first DSP code (Phase 1, task group 4–5) |
| `test-reviewer` | synthetic signals; determinism; numeric tolerances; edge cases; cancellation; concurrency; small fixtures; **no copyrighted material**; regression coverage | first tests (Phase 1) |
| `macos-reviewer` | native macOS UX; drag-and-drop; `fileImporter`; security-scoped bookmarks; sandbox; menus; keyboard; windows; accessibility; permission persistence | first UI (Phase 1, task group 7) |
| `spec-reviewer` | implementation satisfies the approved OpenSpec change; scenarios covered; acceptance criteria verifiable; nothing built outside approved scope | as soon as implementation PRs begin |

Guardrails when they are introduced:

- Agents **recommend**; humans (and the primary session) apply changes.
- Scope each agent to reading + reporting; do not grant overlapping write duties.
- Before authoring them, re-check the installed Claude Code version's agent format rather than
  assuming this document is still current.

## Telemetry

OpenSpec telemetry is disabled for this project via `OPENSPEC_TELEMETRY=0` (see
[privacy.md](privacy.md)). No other AI tooling in this repo collects telemetry.
